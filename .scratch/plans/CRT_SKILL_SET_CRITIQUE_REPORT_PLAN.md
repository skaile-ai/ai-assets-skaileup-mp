## Approach

### Step 1 — Dump script `dump-skill-set-critique-2026-10-15.py`

Location: `.scratch/reports/dump-skill-set-critique-2026-10-15.py`. Stdlib + `yaml` (pyyaml is importable; `scripts/check.py` imports it). Run from repo root: `python3 .scratch/reports/dump-skill-set-critique-2026-10-15.py` → writes `.scratch/reports/skill-set-critique-2026-10-15.data/<collection>.json` (JSON arrays). It reads facts from files; the only hand-held data are the **writer map** and the **findings**, and each row of those carries an evidence citation that the script asserts against the file (see below), so a stale citation aborts the dump.

Collections (one file each):

1. `skills.json` — one row per `skills/*/SKILL.md` (30): `id` (= `name:`), `domain` (first `-` segment; `skaileup` → `collection`), `lines` (file line count), `steps` (count of `^\d+\. \*\*` in body), `description`, `requires` (`metadata.artifacts.requires[].id`), `prereqs` (`[{path, gate, min_entries}]` from `metadata.prerequisites.files`), `inputs_optional` (ids), `contracts` (sorted unique `contracts/<x>.md` cited in body), `contracts_n`, `question_steps` (count of numbered steps whose text matches `/\b(ask|approve|approval|confirm|interview|grill|one question)\b/i`), `glossary_mentions` (count of `glossary` in body), `flows` (flow ids whose nodes carry `data.skill == id`), `phase` (the `data.phase` of that node; `none` when in no flow), `findings_n` (filled from findings.json).
2. `contracts.json` — one row per `contracts/*.md` except `README.md`/`CONTRACT.md` (13): `id` (filename stem), `file`, `lines`, `readers` (skill ids citing it), `readers_n`.
3. `flows.json` — one row per `flows/*/*.flow.yaml` (4): `id`, `nodes_n` (skill nodes), `order` (skill ids along `type: flow` edges from `entry`), `requires_n`, `research_depth` (`globals.research_depth`).
4. `gates.json` — one row per (flow, node in order, prerequisite) (152 rows; 78 hard): `id` (`<flow>:<skill>:<path>`), `flow`, `position` (1-based node index), `skill`, `path`, `gate`, `producer` (the nearest upstream skill in that flow whose writer-map target equals the path or is under it; `null` when none), `satisfied` (bool: producer not null), `prereq_at` (`skills/<skill>/SKILL.md:<line>` of the prerequisite row in frontmatter).
5. `artifacts.json` — one row per artifact target (14 = 11 first-level folders + `brief.md`, `goals.md`, `comparable.md`): `id` (`a-01_meta`, `a-brief`, …), `path`, `writers` (skill ids from the writer map), `writers_n`, `multi_writer` (bool, `writers_n > 1`), `readers` (skills with a prerequisite under the path, plus skills whose body mentions the folder token), `editor_form` (from the file types the tree lists under it in `contracts/concept_structure.md`: `md` → TipTap-editable prose; `yaml`/`json`/`dbml` → code editor; `html` → preview; `mixed`), `kind` = `artifact`.
6. `writes.json` — the writer map, declared in the script as a list of `(skill, path, at, quote)` where `at` is `skills/<skill>/SKILL.md:<line>` and `quote` a substring that must be on that line; the script asserts it and aborts with the row on mismatch.
